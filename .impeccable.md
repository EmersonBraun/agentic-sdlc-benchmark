## Design Context

### Users

Researchers, senior engineers, conference and course audiences, and technically
curious readers use the public dashboard to inspect benchmark evidence, compare
conditions, follow run and ledger provenance, and understand what is verified
versus blocked.

### Brand Personality

Rigorous, transparent, systems-minded. The interface should create confidence
through evidence density, clear uncertainty, and restrained editorial hierarchy.

### Aesthetic Direction

Editorial research-lab: light-first, high-contrast, typographically deliberate,
with restrained ink, paper, and signal colors. Use asymmetrical layouts and
compact data views for analytical density; avoid generic SaaS cards, neon AI
visuals, decorative gradients, and unverifiable “success” metrics.

### Design Principles

1. Every insight must identify its protocol, dataset, and evidence source.
2. Blocked, partial, and verified states must be visually distinct and never
   collapsed into a single success score.
3. Show the smallest useful visualization for each relationship; preserve the
   underlying table or source link for auditability.
4. Treat privacy and redaction as visible product behavior, not hidden plumbing.
5. Make the dashboard useful before any pilot data exists by explaining the
   protocol and showing readiness honestly.
